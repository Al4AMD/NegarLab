## 1. Project

**NegarLab (نگارلب)** is a bilingual (Persian/English) web-based **image-processing laboratory** for the *Multimedia Systems* university course. A student loads an image (or a bundled demo), applies an algorithm, and immediately sees the result: pixel matrix, histogram, spatial and frequency filters, morphology, compression, quality metrics, and lightweight ML tools. Each tool is paired with theory. The app must be usable by real students and instructors, deployed publicly, and demonstrated offline on a normal laptop (CPU-only baseline).

Goals, in priority order: educational correctness, live interactivity, clarity, robustness. Non-goals: accounts, social features, mobile-first design.

## 2. Architecture

```
apps/web        React + TypeScript + Vite SPA (bilingual, RTL default)
apps/api        Python FastAPI backend (ingest, codecs, heavy/ML jobs)
packages/ip     Pure TypeScript image-processing library (no DOM, no React)
tools/golden    Python/NumPy generators for golden vectors
tools/demo_images  Deterministic synthetic demo image generator
docker/         Dockerfiles + Caddyfile; compose.yaml at root
```

| Concern | Runs in | Why |
|---|---|---|
| Pixel math, histograms, filters, FFT, morphology, geometry, toy codecs, metrics | Browser (`packages/ip` in Web Workers) | Live feedback, no server round-trip. |
| Decoding of arbitrary uploads → canonical RGBA PNG; EXIF policy; TTL storage | Backend | Browsers cannot decode every format. |
| Real codecs: JPEG XL, HEIC, JPEG 2000 | Backend (encoders as subprocesses) | Real encoders; never reimplement. |
| JPEG/PNG/WebP/AVIF encode for comparison | Browser (`canvas.toBlob`) | Already available natively; no backend round-trip. |
| ML models | Backend | Heavy; CPU, lazy-loaded, offline volume. |
| Golden/reference values | `tools/golden` (NumPy float64) | Independent ground truth for TS code. |

Hand-write only algorithms that teach something. Use libraries for codecs, FFT internals where not pedagogical, plotting, and ML. Never add a dependency without checking `docs/DECISIONS.md`.

## 3. Stack

- Frontend: React, TypeScript strict, Vite, Zustand, Tailwind CSS v4, i18next/react-i18next (fa default RTL, en), KaTeX (later feature waves), Comlink for workers, Vitest, Playwright smoke.
- Backend: Python 3.11+, FastAPI, Pydantic v2, Pillow, NumPy, uv, pytest, ruff, mypy.
- Package manager: pnpm workspaces. Lint/format: Biome (single tool; do not add ESLint/Prettier).
- Codecs: hybrid strategy — browser native first, backend subprocess for JXL/HEIC/J2K.

## 4. Correctness and testing

- `packages/ip` is the correctness-critical core. Golden vectors are generated in `tools/golden` from an independent NumPy implementation; tolerance 1e-6 unless a test documents otherwise.
- Every new algorithm needs a unit test plus, where numeric, a golden vector.
- API behavior is covered by pytest, including error codes, limits, TTL, EXIF privacy, job cancel, and SSE terminal events.
- Web shell/e2e behavior is covered by Playwright smoke tests; keep the console-error assertion.
- Do not weaken or delete tests to get green. Add a regression test for every bug fix.

## 5. Privacy and security

- EXIF is displayed then stripped. GPS coordinates MUST NOT appear in any response; only `gps_present`.
- Limits: upload ≤25 MiB, ≤64 MP header check before decode, working cap 2048 px, TTL 60 min.
- No secrets in the repo. Do not log image bytes or EXIF values.
- Only synthetic or CC0 demo images. Never commit Lena or copyrighted images.
